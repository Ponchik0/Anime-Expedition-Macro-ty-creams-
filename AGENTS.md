# AGENTS.md — инструкция для ИИ-агента

Этот файл читают Claude Code, Codex, Cursor, Antigravity, Copilot и прочие
агенты, когда открывают репозиторий. Если ты ИИ — прочитай его целиком **до**
первой правки. Если ты человек — здесь же собрано, что просить у агента и чего
от него требовать.

`CONTRIBUTING.md` — это инструкция **автора движка** для его репозитория.
Здесь — правила **этой сборки**, и при расхождении главный этот файл.

---

## 1. Что это за проект

Макрос автофарма для игры **Anime Expeditions** в Roblox. Работает **зрением**:
снимает окно игры и ищет на нём заранее нарезанные картинки. Никаких инъекций
в процесс, никакого чтения памяти.

- **Python 3.10+** + **pywebview**: окно приложения — это WebView2, то есть
  обычная веб-страница. Вся вёрстка в `ui/` — HTML/CSS/JS.
- Окно Roblox **встраивается внутрь** окна макроса (`SetParent`, `core/dock.py`).
- Размер окна игры фиксирован — **1152 × 756**. Поэтому все координаты в коде
  живут в одной системе и «пересчёт под любой размер» тут не нужен.
- Платформа — **Windows**. macOS-пути в коде есть, но это не основной сценарий.

Это **форк**. Апстрим — `Cweamy/Anime-Expeditions-Creams-Macro`, наш репозиторий
— `Ponchik0/ae`. Подробности в разделе 6.

Раньше это был макрос на AutoHotkey. Всё ценное оттуда (координаты, пороги,
наблюдения за интерфейсом игры) перенесено в `docs/from_ahk.md` — **это не
архив, а справочник**, туда стоит заглядывать при работе с координатами.

## 2. Быстрый старт

```bash
python -m venv venv
.\venv\Scripts\Activate.ps1          # PowerShell
pip install -r requirements.txt
pip install -r requirements-dev.txt

python main.py                       # запустить приложение
python -m pytest tests/ -q           # тесты (~2 минуты, ~940 штук)
node --check ui/app.js               # синтаксис фронтенда
```

**Перед тем как сказать «готово», обязаны пройти обе проверки:**
`python -m pytest tests/ -q` и `node --check ui/app.js`.

## 4. Два режима работы — не перепутай

Это главное, чего не понимают агенты, пришедшие в проект впервые.

**Автомат (`run_mode: "auto"`)** — `core/runner.py`. Макрос сам ходит по меню
игры, узнаёт кнопки по картинкам, проверяет результат. Умный, но требует
настройки: шаблоны, координаты, сценарии.

**Повтор (`run_mode: "replay"`)** — `core/replay.py`. Записывает действия
игрока тик в тик и крутит их по кругу. Об игре не знает **ничего**. Настраивать
нечего.

Кнопка «Старт» одна на оба режима — что она делает, решает `run_mode`
(см. `Api.start_macro`).

### Грабли режима «Повтор»

Они выписаны в шапке `core/replay.py` — **прочитай её перед любой правкой этого
файла**. Коротко:

1. Часы — только `time.perf_counter()`. Системный тик Windows ~15.6 мс.
2. Расписание **абсолютное**, а не «спать между событиями»: иначе опоздания
   планировщика копятся и записанная минута растягивается в полторы.
3. Отстали больше чем на круг — пропущенное **не отыгрываем**.
4. Автоповтор зажатой клавиши схлопывается в одно «держу».
5. **Ждать — это тоже действие.** Длина круга берётся из `duration`, а не из
   времени последнего события: типичная запись — расставил юнитов и досидел
   матч молча.
6. Клики по собственному окну макроса в запись не попадают.
7. Окно игры (`hwnd`) спрашивается **каждый тик**, и в записи, и в повторе:
   Roblox посреди прогона перезапускается, и старый `hwnd` мёртв. При смене
   окна — отпустить зажатое, пересчитать масштаб, начать круг заново.
8. Пауза перед первым действием (`START_DELAY_MS`, настраивается): окно Roblox
   возвращается на экран не мгновенно, и без паузы первые нажатия круга уходят
   в никуда.
9. Заслонка «только при активном окне» — это `game_active` (**видно И в
   фокусе**), а не `_game_focused`. Встроенная игра прячется на любом экране
   кроме Панели, фокус при этом остаётся на окне макроса, и одной проверки
   фокуса хватало, чтобы жать кнопки в спрятанное окно.
10. Исход матча засчитывается только после **двух опросов подряд**
    (`CONFIRM_SIGHTINGS`): один кадр может быть анимацией или наложением, а
    ложная победа портит винрейт навсегда.

## 5. Правила этой сборки

Нарушение этих правил = правку придётся переделывать.

### 5.1 Комментарии объясняют ПОЧЕМУ, а не ЧТО

В этом коде комментарий — это объяснение решения, а не пересказ строки.
Плохо: `# увеличиваем счётчик`. Хорошо: объяснение, из-за какого бага здесь
именно так и что сломается, если сделать иначе. Смотри существующие файлы —
там этот стиль выдержан, держи его.

Комментарии и docstring — **по-русски**, как во всём проекте.

### 5.2 Язык интерфейса

- Экраны **Панель, Задачи, Сценарии, Настройки** написаны **по-английски**,
  русский к ним приходит словарём `ui/i18n.js`. Добавляешь туда новую подпись —
  пиши её по-английски и **добавь ключ в словарь**.
- Экраны **«Запись»** и окно записей написаны **по-русски напрямую** — они так
  и задумывались. Там русский в разметке.
- Ключи словаря **глобальные**: один и тот же английский текст переводится
  везде. Перед добавлением проверь, нет ли такого ключа (`'Clear'` уже есть).
- Журнал процесса **не переводится никогда** — это вывод макроса.

### 5.3 Никаких нативных `confirm()`/`alert()` на Панели

Они рисуются **за** встроенным окном Roblox — человек увидит зависшее
приложение без единой кнопки. Вместо этого — двухшаговая кнопка
(`clearRunHistory` в `ui/app.js`, `deleteTemplateImage` там же) или свой модальник.

### 5.4 Тесты

- Пишутся **без** Windows-вызовов, без Roblox, без курсора — они идут и на CI.
  Настоящие вызовы подменяются через `monkeypatch`.
- Имя теста — предложение о поведении, а не `test_func_1`.
- Docstring теста объясняет, **какой баг он ловит**. Посмотри
  `tests/test_replay_wait_time.py` — это образец.

### 5.5 Настройки

Всё через `core/settings.py`: `cfg.load()` и `cfg.update({...})`. Новый ключ
обязан иметь значение по умолчанию **в коде**, чтобы свежая установка работала,
и обязан переживать мусор в `settings.json` (его правят руками).

### 5.6 Объём правки

Делай то, о чём попросили. Рискованное и «заодно улучшил» — отдельно и после
явного «да». Не переписывай `ui/style.css` построчно (см. ниже).

## 6. Обновление с GitHub автора (важное)

У репозитория два удалённых адреса:

```
origin    https://github.com/Ponchik0/ae                            ← наш форк
upstream  https://github.com/Cweamy/Anime-Expeditions-Creams-Macro  ← автор движка
```

### Как подтянуть обновления автора

```bash
git fetch upstream
git log --oneline HEAD..upstream/main        # что нового у автора
git checkout -b merge/upstream-vX.Y.Z        # ОТДЕЛЬНАЯ ветка, не в main
git merge upstream/main
```

Дальше — руками разобрать конфликты. **Правила разбора:**

| Файл | Как мёржить |
|---|---|
| `ui/style.css` | **НЕ мёржить построчно.** Он переписан с нуля под эту сборку. Взять свою версию целиком, а нужное из апстрима перенести осознанно |
| `ui/i18n.js` | наш файл, у автора его нет. Взять свой + дописать ключи для новых английских подписей апстрима |
| `core/replay*.py`, `core/report_pdf.py` | наши модули, у автора их нет — конфликтов быть не должно |
| `core/`, `main.py` | обычный мёрж, но проверь, не потерялись ли наши методы `replay_*` и `_record_match_result(source=...)` |
| `Assets/` | картинки автора **не перетирать** своими и наоборот — они подбираются под конкретную графику |

После мёржа — **обязательно**: `python -m pytest tests/ -q` и
`node --check ui/app.js`. Плюс запустить приложение и пройти по экранам
глазами: тесты не ловят разъехавшуюся вёрстку.

Историю прошлых мёржей смотри в `git log --merges`.

### Самообновление готовой сборки

Это другое: `core/updater.py` тянет релиз с **нашего** GitHub, а не с апстрима.
Настройки → «Проверить обновления». Собранный `.exe` заменяет себя сам.
Картинки из `Assets/` при этом **добавляются, но не перетираются** — свои
правки эталонов не потеряются.

**Репозиторий обязан оставаться публичным.** Проверка версии ходит туда
анонимно, а приватному репозиторию GitHub отвечает анонимному гостю `404`
(именно 404, а не 403, — чтобы не выдать сам факт его существования). В
журнале это выглядит так:

```
[Update] https://github.com/Ponchik0/ae/releases/latest ответил 404, репозиторий недоступен.
[Update] Couldn't check: the update repository is private, renamed or deleted.
```

Так и было, пока репозиторий побывал закрытым. Токеном это не лечится: токен,
положенный в приложение, достаётся из него за минуту. Если исходники всё-таки
понадобится закрыть — заводится отдельный маленький публичный репозиторий
только под релизы и вписывается в `RELEASES_REPO` (`core/updater.py`, там
расписан весь список правок). Всё сетевое ходит через эту константу.

### Выпуск релиза

**ВАЖНО: Формат описания релиза строго стандартизирован.**
Никаких пустых релизов и однострочников. GitHub Actions читает текст тега (`git tag -a vX.Y.Z -m "..."`) и публикует его как описание релиза. Стиль оформления строго как в `v1.1.7` / `v1.1.11`:

```markdown
## vX.Y.Z — Главная тема релиза через тире

### Название первой темы/модуля
- `new` **Название фичи** — подробное описание на английском (или русском), что добавлено.
- `fix` **Название бага** — что именно исправлено и почему больше не падает.

### Название второй темы/модуля
- `new` **...** — ...
- `fix` **...** — ...

### Quality & Bugfixes
- `fix` **100% Test Coverage** — прохождение тестов, валидация синтаксиса.

---

### How to update:
- **In-app:** Settings → "Check for Updates".
- **Direct download:** Download `Anime Expeditions Macro Setup.exe` from the release assets below.

> [!IMPORTANT]
> When updating manually from a `.zip` archive, make sure the `Assets` folder is placed next to the `.exe` file. The automatic installer updates all files preserving your settings.
```

**Команды для релиза:**
```bash
# 1. номер в VERSION = номеру тега. Это одно и то же число, разными словами:
#    VERSION — «что стоит у меня», тег — «что вышло», и сравниваются именно они
echo 1.1.1 > VERSION && git commit -am "Bump VERSION to 1.1.1" && git push

# 2. Текст тега — строго в формате выше (через файл с флагом --cleanup=verbatim, иначе git вырежет все заголовки с # как комментарии!):
git tag --cleanup=verbatim -a v1.1.1 -F release_notes.txt
git push origin v1.1.1
```

Дальше `.github/workflows/release.yml` соберёт сборку и опубликует релиз сам.

**Тег ниже, чем VERSION, — это не релиз, а тишина.** Живой случай: тег
`v1.0.1` при `VERSION` 1.1.0. Проверка прочитала «у тебя уже новее» и ответила
«последняя версия» — обновление не предложилось никому. Название релиза на это
не влияет вообще, оно просто текст.

## 8. Чего агент сделать НЕ сможет

Скажи об этом прямо, а не делай вид, что проверил:

- **Запустить игру.** Roblox, встраивание окна, реальные клики — только руками.
- **Проверить совпадение эталонов.** Совпадают ли `Assets/ui/victory/*.png` на
  конкретной машине — видно только на живом экране.
- **Проверить вёрстку.** Тесты не смотрят на экран. Разъехавшуюся панель увидит
  только человек.
